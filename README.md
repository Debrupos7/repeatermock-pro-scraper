# RepeaterMock PRO Scraper v3

Scrapes **all 9,915 PRO (paid) tests** from RepeaterMock using **3 paid accounts in parallel** + **4 ZenRows API keys** for Turnstile bypass.

## What's new in v3

- **3 PRO accounts** running in parallel (1 worker per account) — finishes all 9,915 tests in ~5h (down from 16h)
- **4 ZenRows API keys** with automatic rotation when one runs out of credits
- **Smart token refresh**: only refreshes accessToken every 14 min (when it actually expires), no repeated calls
- **5-error stop**: after 5 consecutive scrape failures (not rate-limit 429s), worker stops cleanly and saves progress
- **5.5h max runtime** per worker (well under the 20-hour account lockout window)
- **Same folder structure as free scraper**: `pro_scraped_output/{series_slug}/ai_export/...` and `html_export/...`
- **Per-worker progress files**: `progress_worker_1.json`, `progress_worker_2.json`, `progress_worker_3.json` (avoids concurrent write conflicts)
- **Auto-trigger next round**: after all 3 workers finish, if any tests remain, automatically triggers a new run

## Required GitHub Secrets

| Secret | Description |
|--------|-------------|
| `RM_EMAIL_1`, `RM_PASSWORD_1` | Account 1 credentials |
| `RM_EMAIL_2`, `RM_PASSWORD_2` | Account 2 credentials |
| `RM_EMAIL_3`, `RM_PASSWORD_3` | Account 3 credentials |
| `ZENROWS_API_KEYS` | Comma-separated list of 4 ZenRows API keys |
| `GH_PAT` | GitHub Personal Access Token for triggering next round |

## How to run

1. Go to https://github.com/Debrupos7/repeatermock-pro-scraper/actions/workflows/scrape-pro-matrix.yml
2. Click "Run workflow"
3. Leave `max_tests` empty for full run (~3,305 tests per worker)
4. Leave `max_runtime` at default `330` (5.5h per worker)
5. Click green "Run workflow" button

For a **test run** (40 tests per worker, ~5 minutes): Set `max_tests=40`

## Stop conditions

A worker stops and saves progress if:
1. **5 consecutive scrape errors** (not 429s — those are retried)
2. **3 consecutive auth failures** (login or refresh)
3. **5.5h max runtime** reached
4. **All assigned tests completed**

When any worker stops, the `trigger_next_round` job automatically counts remaining tests across all workers and triggers a new run if any remain.
